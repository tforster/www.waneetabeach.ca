## 1. Overview

| Table | Owned by | Purpose |
| :--- | :--- | :--- |
| `categories` | App | Fixed set of thread categories |
| `threads` | App | Top-level discussion threads |
| `posts` | App | Replies within a thread |
| `user` | Better Auth | Member identity (created in issue #4) |
| `session` | Better Auth | Active login sessions |
| `account` | Better Auth | OAuth / credential accounts |
| `verification` | Better Auth | Email verification tokens |

Better Auth owns the `user` table and supports custom field extension. The `active` field (for account deactivation) is added via Better Auth's schema configuration rather than a hand-written migration.

`author_id` columns in `threads` and `posts` reference Better Auth's `user.id`. A FK constraint will be added in a follow-up migration once the `user` table exists.

## 2. Tables

### 2.1. categories

Fixed lookup table. Rows are seeded by `migrations/0002_seed_categories.sql` and are never user-configurable.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | Stable short identifier (e.g. `cat_road`) |
| `slug` | TEXT | NOT NULL, UNIQUE | URL-safe identifier |
| `label` | TEXT | NOT NULL | Display name |
| `sort_order` | INTEGER | NOT NULL, DEFAULT 0 | Display ordering |

**Seed rows**

| id | slug | label | sort_order |
| :--- | :--- | :--- | :--- |
| `cat_road` | `road-maintenance` | Road & Maintenance | 1 |
| `cat_events` | `events` | Events | 2 |
| `cat_snow` | `snow-removal` | Snow Removal | 3 |
| `cat_general` | `general` | General | 4 |

### 2.2. threads

One row per discussion thread.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | UUID generated by the Worker |
| `category_id` | TEXT | NOT NULL, REFERENCES categories(id) | Thread category |
| `author_id` | TEXT | NOT NULL | Better Auth `user.id` of the poster |
| `title` | TEXT | NOT NULL | Thread subject (max 120 chars enforced in API) |
| `body` | TEXT | NOT NULL | Thread body |
| `created_at` | TEXT | NOT NULL, DEFAULT datetime('now') | ISO 8601 UTC timestamp |

### 2.3. posts

Replies to a thread. Flat — no nesting.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | TEXT | PRIMARY KEY | UUID generated by the Worker |
| `thread_id` | TEXT | NOT NULL, REFERENCES threads(id) | Parent thread |
| `author_id` | TEXT | NOT NULL | Better Auth `user.id` of the poster |
| `body` | TEXT | NOT NULL | Reply body |
| `created_at` | TEXT | NOT NULL, DEFAULT datetime('now') | ISO 8601 UTC timestamp |

### 2.4. Better Auth tables

Generated and managed by Better Auth. See [Better Auth D1 documentation](https://www.better-auth.com/docs/adapters/cloudflare-d1) for the full schema. Applied during issue #4 setup.

## 3. Migrations

| File | Description |
| :--- | :--- |
| `migrations/0001_schema.sql` | Creates `categories`, `threads`, `posts` tables |
| `migrations/0002_seed_categories.sql` | Inserts the four fixed categories |
| `migrations/0003_better_auth.sql` | Creates Better Auth `user`, `session`, `account`, `verification` tables |
| `migrations/0004_admin_plugin.sql` | Adds `role`, `banned`, `banReason`, `banExpires`, `impersonatedBy` columns |

Migration files use sequential numeric prefixes. `cf` tracks which migrations have been applied in the `d1_migrations` table, using the same format as Wrangler.

## 4. Applying migrations locally

Apply all pending migrations to the local databases:

```bash
npm run migrate:local
```

See [How to Deploy the Worker Ecosystem](../how-to-guides/deploy-workers.md) for remote migrations and for querying the local databases.
